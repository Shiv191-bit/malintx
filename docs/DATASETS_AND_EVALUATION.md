# Datasets and evaluation

MALINT-X ships **no malware and no real app samples**. The test suite uses inert synthetic APKs generated by `tests/apkbuilder.py` (valid AXML/DEX/ZIP containing only method references). Their results verify plumbing and rule logic; they are never evidence of real-world accuracy and the evaluation runner says so in its output.

## Tiered strategy (from the SENTINEL spec) and access reality
| Tier | Source | Access (verified where noted) | Use |
|---|---|---|---|
| 1 | MalwareBazaar | Free `Auth-Key` from auth.abuse.ch; fair-use; commercial use may need a paid plan; daily limits; samples are AES zips with password `infected` (verified 2026-11-03). | Malicious corpus; family labels from `signature` |
| 1 | Koodous | API unstable per its own docs; terms unconfirmed. | Optional; do not depend on it |
| 2 | AndroZoo | Research access by request; terms not verified (site unreachable during audit). | Benign corpus (incl. banking apps) |
| 2 | F-Droid | Public repository; open-source licences apply per app. | Clean baseline with source |
| 3 | MITRE ATT&CK for Mobile | Public; vendored v20.0 STIX, SHA-256 in `/config` | Ontology (done) |
| 3 | OWASP MASVS | Public; control IDs in `data/masvs/` (hand-transcribed, verify upstream) | Posture mapping |

Download and handle malware only inside an isolated VM. Keep original archives and licences; do not redistribute samples.

## Workflow
```
malintx-eval init <dir>  > manifest.json     # dir/{malicious,benign}/*.apk; provenance defaults to "unknown"
# edit manifest.json: real source, retrieved_at, label, family, split, expected_techniques
malintx-eval validate manifest.json          # schema, SHA-256 of every file, provenance rules, split leakage
malintx-eval calibrate manifest.json         # picks the decision threshold on the calibration split ONLY
malintx-eval run manifest.json --split test --threshold <chosen> --repeats 3 --out eval_out
```
Rules enforced by the manifest: `wild_caught` / `curated_benign` / `open_source_build` require a documented source and `retrieved_at` (otherwise use `unknown`); a sample may not appear in two splits or twice.

## Reported metrics
Precision, recall, F1, false-positive and false-negative rate with **Wilson 95% CIs**; abstention rate (`inconclusive`/`insufficient_evidence`/`analysis_failed` are never converted into a verdict: abstaining on malware counts against recall, abstaining on benign is reported separately and is not a false positive); duration (mean/median/p95); extraction coverage; scoring consistency across repeats (same inputs digest and score); ATT&CK technique precision/recall for deterministic rules and, when run with `--ai`, for AI claims (`n/a` otherwise). Per-sample table and provenance breakdown included.

## Current state
No real corpus has been run. Any figure in the original SENTINEL/PPT material (e.g. 97.8%, 98.4% zero-day) comes from the cited papers' ML models, not from MALINT-X, and must not be presented as MALINT-X performance.
